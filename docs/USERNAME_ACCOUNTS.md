# 用户名注册、管理员后台与保持登录

此方案是当前最新方案，取代“新用户必须使用邮箱验证码”。无需继续配置 SMTP。原有邮箱账号仍可从“已有邮箱账号登录”进入，记录不自动迁移或合并。

代码已实现，但必须由项目所有者在真实 Supabase 执行一次升级后才启用。当前云环境不能连接该项目，不能代执行 SQL、创建真实管理员或验证线上登录。SQL 安装前网页会保留原邮箱入口，避免新版前端先于数据库发布导致登录中断。

## 一次性启用（只需在 Maths Library 操作）

1. 打开 Supabase → **Maths Library → SQL Editor → New query**。
2. 从仓库打开 [`05_username_accounts.sql`](../supabase/shared/05_username_accounts.sql)，点击文件右上角复制按钮，复制**整份**到 SQL Editor，点 **Run**。预期一行 `username_accounts_installed=true`、`mode=username`。这是已安装共享后端的升级；不要重跑 01，不要把独立项目的 001 用在这里。
3. 再建一个查询，执行 [`07_verify_username_accounts.sql`](../supabase/shared/07_verify_username_accounts.sql)。六项应全部为 `true`。这份结果没有私密信息，可以提供截图；出错请保留原报错，勿删除表或触发器。
4. 刷新学习网站，应出现“用户名登录 / 注册账号”。注册填写用户名、密码和确认密码即可，无需真实邮箱或验证码。普通用户注册密码至少 6 位；用户名 2–24 个中英文字母、数字或下划线，英文字母不区分大小写，全角字符先规范化。

这份升级只新增 study_* 对象和专属触发器，扩展学习数据权限函数；不修改 pp_new_user、原数学触发器、数学记录、sixsigma 或全局 Auth 设置。保持现有 Confirm email 关闭；若项目当前已开启确认，先告知维护者，不应自行改变数学项目的全局设置。

## 初始化两位管理员（邀请码请保密）

1. SQL Editor 新建查询，执行 [`06_create_admin_invites.sql`](../supabase/shared/06_create_admin_invites.sql)。结果是 Kevinwang 和 Jackwang 各自的**一次性邀请码**，24 小时有效。不要截图发到聊天，也不要提交到 GitHub。重复执行只会替换尚未使用的邀请码。
2. 在学习网站选择“注册账号”，输入 **Kevinwang**，在网页私下输入指定的初始密码（此入口至少 8 位），填写该行对应的邀请码，注册。首次登录会要求设置不同的新密码；未完成前，服务器拒绝学习数据及后台访问。
3. 退出后，以 **Jackwang** 和其对应邀请码重复操作。也可以在另一个浏览器中初始化。
4. 更换密码后侧栏出现“管理后台”。管理员账号也可以正常使用学习功能。

聊天中提供过的密码没有写入代码、SQL 或仓库，也没有被用来自动创建账号。Kevinwang 指定的初始密码为 8 位，管理员初始化入口允许至少 8 位，首次登录更换的新密码至少 12 位。此处没有核实真实 Supabase 的服务端密码策略；如服务端要求更长密码，请私下选用符合要求的初始密码，不要降低共享项目的全局策略。两人的密码都曾出现在聊天中，初始化后请使用新的私密密码。浏览器不会保存密码正文，只由官方客户端保存并续期登录会话。注册时先使用不持久化的临时客户端，再重新读取数据库已去除邀请码的用户资料；不会把注册响应中的邀请码写入登录缓存。

普通注册者仅凭这两个用户名或伪造 user_metadata.role 不能成为管理员；邀请码生成函数只授权给数据库所有者。管理员不能从后台删除自己或另一管理员，管理员维护由 Supabase 项目所有者处理。仅保留用户名无需发邮件的注册模式不提供邮箱找回；遗忘密码需要联系项目所有者，不应删除含学习数据的账号来“重置”。

## 管理能力与时间记录

- 后台分页搜索本站用户名账号；显示注册、最近登录、最近退出时间，查看最近 180 天的登录/退出记录。原数学账号和旧邮箱账号不能在这里管理。
- 可以停用、启用、移入回收站及恢复普通用户。停用/回收会立即阻断其现有令牌访问学习数据库；在线网页在聚焦或下一次检查时锁定（通常不超过 5 秒）。已保存到用户设备的副本不能远程擦除。
- 永久删除必须先移入回收站，再在原生确认对话框输入完整用户名。删除该用户的 Auth 身份、会话、云端学习工作区和操作回执；操作在一个事务中执行，失败不会留下部分删除。审计记录保留，不含密码或完整 Auth payload。
- 登录来自 Auth 服务审计；在托管服务不保存 PostgreSQL 审计时，使用 Auth 写入的 last_sign_in_at 记录。退出在 Auth signOut 成功后，使用内存中的原签名令牌核验对应 auth.sessions 已移除，再写入服务器时间；当前浏览器不能记录其他人的退出。
- 关闭网页、离线、浏览器崩溃、令牌自然失效不伪装成明确退出。同一用户可在多个设备登录，因此“最近退出”不代表其所有设备离线。网络中断可能使退出审计缺失，界面会显示暂无服务端记录。
- 登录事件保留 180 天，后续事件写入会清理过期登录记录；不是严格定时擦除。管理员操作审计单独保留供项目所有者检查。

## 同一终端免重复输入

普通用户和管理员都默认保持当前浏览器登录；刷新、关闭后重新打开、新标签页会恢复同一会话，令牌由 Supabase SDK 自动续期。没有将账号密码自动填入或明文保存。主动退出、会话撤销、浏览器清理存储或续期失效后需要重新登录。“同一终端”指同一浏览器和配置文件；微信内置浏览器、Safari、Chrome 的存储彼此独立，无痕窗口通常不会长期保留。

## 验证范围与恢复

`npm run test:username` 在隔离 PostgreSQL 中安装精确 CRLF 数学 fixture、既有共享层和本次升级，验证权限、管理员邀请、强制改密、停用旧令牌、回收/恢复、级联删除、原数学兼容以及审计。浏览器契约测试覆盖桌面和 390px 手机注册、刷新/新标签恢复、退出清除、管理员改密、管理操作和停用后锁定；API 响应为模拟，不能替代真实托管 Auth 验收。

真实验收：完成以上 SQL 与管理员初始化后，注册一个测试普通账号，记录一条学习数据，退出重登及另一个设备登录检查；管理员停用后确认其无法同步，恢复后数据仍在；测试账号移入回收站、恢复、最后永久删除。再确认数学网站原账号注册/登录/记录均正常。不应使用真实学习主账号测试永久删除。

升级事务失败会整体回滚；不要拆段执行。不要在升级后直接运行旧版 `02_disable_shared.sql`：旧版撤销脚本不了解新账号接口。需要回退时应由维护者检查并提供专项迁移，保留现有数据；前端可以通过 GitHub 回退提交，旧邮箱账号仍使用原入口。

普通用户注册的网页最低长度现为6位；管理员初始化与首次改密要求保留。无需重跑安装 SQL。服务端最低长度仍由 Supabase Auth 项目策略决定，网页不能绕过服务端限制。
